## Bug：≤30分钟手持单仍被插单

### 计划

- [x] 核查当前任务类型数据库配置与派单插单代码路径。
- [x] 修复待就位抢占路径漏检查「可被插单」的问题。
- [x] 后端统一强制 `maxDuration <= 30` 不可被插单，避免旧数据/前端显示不一致。
- [x] 修正分类保存接口，使保存时同步落库不可插单规则。
- [x] 回归验证并记录结果。

### 评审

- 根因：执行中插单会检查 `canBeInterrupted`，但待就位抢占路径 `interruptWaitingPreempt` 漏查，导致「待就位」状态的手持 5-15 分钟仍会让行紧急单。

- 已修复：派发逻辑统一通过 `taskCategoryCanBeInterrupted` 判断；执行中插单和待就位抢占都会读取并尊重任务类型配置。
- 已修复：分类新增/编辑接口会把 `maxDuration <= 30` 强制保存为不可插单，避免前端设置和后台派发再次不一致。
- 已同步当前数据库：所有 `maxDuration <= 30` 的任务类型已改为 `can_be_interrupted=0`。
- 已清理当前错误生成的插单关系；浏览器复核不再显示「已让行紧急单」，叶梦妮当前显示为执行中手持 5-15分钟。
- 验证通过：`taskCategoryCanBeInterrupted` 回归断言通过，`npx tsc --noEmit` 通过。

## 待确认：多人协作独立状态模型

### 目标

- 每个参与助理都有自己的就位、进行中、完成状态。

- 主助理不再独占任务完成权；主助理和协作助理都只是任务参与者之一。

- [ ] 摄影师端任务卡片展示每位助理的独立状态和整体完成进度。
- [ ] 自动派单只给主助理；摄影师手动添加协作助理后，该助理进入自己的待就位状态。
