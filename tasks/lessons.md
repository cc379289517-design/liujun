# Lessons

- Prisma schema 新增字段并 `prisma generate` 后，本地 Next dev server 可能仍持有旧客户端；涉及新增 Prisma 字段的 API 回归前需要重启 dev server。
- 区分“待就位让行”和“执行中插单”：前者是队列重排，不应复用任务类型可插单限制；后者才需要严格按后台可插单、30分钟内不可插单和最大离场时间配置执行。
- 不要用人员 `updatedAt` 推算业务状态持续时间；资料更新、楼座切换、在线状态切换都会刷新它。像“吃饭中计时/冷却”这种行为状态要有独立开始/结束时间，并在接口层强制校验。
- 身份切换弹窗里的小菜单要同时处理 `pointerdown`、`mousedown` 和 `click` 冒泡；只拦 `click` 容易出现菜单能展开但菜单项点不到或被外层行交互抢走。
- 判断助理是否“暂停中可切状态”时，要同时考虑主助理任务和 `TaskCollaborator` 协作任务；多人协作下只查 `bookingTask.assistantId` 会误判并拒绝状态切换。
- Next dev server 的服务端 HTML 可能在热更新后仍保留旧 Client Component 预渲染结果；遇到客户端已更新但 SSR class 仍旧、出现 hydration mismatch 时，重启 dev server 并清理 `.next` 后再做最终截图验证。
- 身份切换面板默认应该是“选择身份/查看状态”，不要让管理账号在这里直接代改助理业务状态；在线/吃饭/休假这类会影响派发的状态变更必须先校验当前身份本人。
- 自动适配视图的逻辑要区分“系统模式切换”和“数据刷新”：用户拖拽/缩放接管地图后，轮询刷新不应再强制覆盖 `zoom/pan`，只有楼座切换、抽屉开合这类明确模式变化才重置手动状态。
- 解决统计面板遮挡时，优先让面板回到 grid/flex 轨道内受布局约束；不要用脱离布局的 `absolute + min-width` 去“顶层显示”，否则会在窄窗口覆盖相邻区域，浮层类内容再单独用 fixed 并按视口夹紧。
- 在带 `transform` 动画的面板内部不要直接渲染 `position: fixed` 浮层；浏览器会把 transformed ancestor 当作 fixed 的包含块，导致坐标错位或看起来不显示。工具提示、明细气泡这类浮层应使用 Portal 挂到 `document.body`。
- 主题、时间、窗口尺寸、localStorage 等客户端专属值不要放进 `useState` 初始化函数参与首帧渲染；Next SSR 会用服务端默认值，客户端首帧如果直接读取本地值就会触发 Hydration mismatch。应先用稳定默认值，挂载后再读取并切换。
- 自动换人和自动离线必须解耦：待就位超时可以把该任务换给别人，但旧助理是否离线要先查她是否还有其他执行中/暂停中的主任务或协作任务，避免把正在工作的助理误判下线。
- 弹窗内表头要吸附到整个弹窗顶部时，不能让表格再包一层独立纵向滚动；同时要用 `elementFromPoint` 复核数字入口的真实命中层，避免后渲染的指标按钮覆盖点击区域。
- 大范围后台 UI 统一优先使用页面作用域外壳承接基础样式，再给表格、弹窗、浮层、工具条等高频组件加语义类；这样能降低影响前台工作台的风险。
