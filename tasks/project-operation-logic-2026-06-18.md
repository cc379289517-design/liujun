# 2026-06-18 项目运转逻辑记录

> 历史归档：本文保留当日讨论和决策上下文，不再作为当前运行规则入口。当前唯一有效入口为根目录 `摄影助理自动派单系统.md`；如本文与主文档冲突，以主文档为准。

> 来源：根据 2026-06-18 与用户对话中已确认的业务口径整理。本文只记录业务运转逻辑和数据口径，不记录普通 UI 微调流水。

## 1. 后台数据统计定位

- 后台「数据统计」页不再只是任务状态列表，而是运营看板。
- 页面目标是帮助管理者按时间、部门、楼座查看任务运转效率、助理贡献、摄影师发布情况和任务明细。
- 统计页以筛选后的统一任务集合为基础，所有总览、排行、趋势和明细应使用同一套筛选口径，避免上方数字和下方明细不一致。

## 2. 日期筛选口径

- 数据统计需要支持快捷日期筛选：
  - 今日
  - 本周
  - 上周
  - 本月
  - 上月
  - 自定义开始日期 / 结束日期
- 日期筛选默认按任务 `createdAt` 归入发布日期。
- 趋势图可以同时展示每日发布量和每日完成量：
  - 发布量按 `createdAt`。
  - 完成量按 `completedAt`。
- 自定义日期的结束日期按自然日包含处理，即选择 `6/18` 时应包含 `6/18 00:00:00` 到 `6/18 23:59:59` 的任务。

## 3. 组织范围筛选

- 数据统计需要支持三类查看范围：
  - 全部范围。
  - 按助理部门查看。
  - 按楼座查看。
- 助理部门直接对应人员资料里的 `department` 字段。
- 当前已确认的核心部门：
  - 一部
  - 二部
  - 全域优化组
- 如果人员资料中存在其他历史部门字段，也可以显示在筛选项里，但核心业务口径以上面三类为准。
- 楼座统计口径：
  - 优先使用任务 `locationBuildingId`。
  - 没有 `locationBuildingId` 时，退回摄影师所属楼座 `photographer.buildingId`。

## 4. 助理排行与贡献值

- 助理排行以已完成任务为基础。
- 主助理和协作助理都应计入完成贡献。
- 贡献值不按点赞/点踩临时加减分，而是沿用主工作台已确认的「助理综合评分」方案。
- 综合分公式：
  - `综合分 = 实际服务时长(1小时=1分) + 完成任务数 × 0.2 + 跨区次数 × 0.2`
- 实际服务时长：
  - 使用任务/参与者的有效工作时长。
  - 等待、待就位、暂停、插单占用等非真实服务时间不计入。
- 完成任务数补贴：
  - 每完成 1 个任务加 `0.2` 分。
- 跨区补贴：
  - 按同一助理在筛选范围内的完成时间排序。
  - 相邻完成任务的楼座不同，计 1 次跨区。
  - 每次跨区加 `0.2` 分。
- 点赞/点踩仍然要在助理排行中展示，但只是评价数据，不参与当前贡献值计算。

## 5. 摄影师发布情况

- 摄影发布情况需要展示：
  - 发布总任务。
  - 已完成任务数。
  - 已完结超时任务数。
  - 该摄影师发布最多的任务类型。
- 超时任务只统计「已完结任务」里的超时数量。
- 已完结超时判断：
  - 任务状态为 `completed`。
  - 存在 `completedAt` 和 `estEndTime`。
  - `completedAt > estEndTime` 才算超时。
- 未完成但当前已经超过预计结束时间的任务，不计入后台统计页的「已完结超时任务数」。

## 6. 任务类型归并

- 统计页任务类型需要简化为五类：
  - 手持
  - 穿戴
  - 手工
  - 熨烫
  - 其他
- 归并口径：
  - 名称包含「手持」归为手持。
  - 名称包含「穿戴」或「服装」归为穿戴。
  - 名称包含「手工」或「DIY」归为手工。
  - 名称包含「熨烫」归为熨烫。
  - 其他无法识别的任务归为其他。
- 摄影师名字后方、任务类型标签、统计页任务类型占比都应尽量使用这套简化口径，避免同类任务显示过碎。

## 7. 任务明细筛选

- 数据统计底部任务明细需要支持：
  - 搜索摄影师姓名。
  - 搜索助理姓名。
  - 用中文姓名首字母快速搜索。
  - 按部门筛选。
  - 按楼座筛选。
  - 按任务类型筛选。
  - 按任务优先级筛选。
- 姓名搜索同时匹配摄影师、主助理、协作助理。
- 首字母搜索作为快捷辅助，不要求完整拼音库；先覆盖常见中文姓氏/姓名首字母即可。
- 明细表头应固定在明细容器顶部，滚动明细内容时表头不离开容器。

## 8. 任务类型与人员标签展示

- 摄影师名字后方需要展示任务类型字符。
- 摄影师名字和任务类型之间需要有分割线。
- 如果摄影师有多个任务队列，任务类型用 `/` 分隔。
- 任务类型展示使用简化字段：
  - 手持
  - 穿戴
  - 手工
  - 熨烫
  - 其他
- 任务类型标签可以使用与快捷预约一致的色块和字体颜色。
- 设计上保持克制，不能为了标签导致人物气泡变得过宽或拥挤。

## 9. 公共队列与地图气泡顺序

- 公共队列中的人员/头像/任务展示顺序应与实际队列顺序一致。
- 排列顺序应按真实优先级权重和队列规则，不应按「X单」数量排序。
- 离线人员气泡间隔应与上方其他气泡间隔保持一致。
- 已确认原本位置合适的气泡不要随意移动；只调整存在拥挤或压住问题的那一排。
- 气泡之间需要保留少量间距，不能互相压住。

## 10. 任务类型占比悬浮信息

- 鼠标移动到彩色饼状图时，需要在旁边显示对应任务类型信息。
- 信息分两排：
  - 第一排：任务类型。
  - 第二排：`X单，占比X%`。
- 引导线样式：
  - 从饼图扇区斜线延伸出来。
  - 再接一段水平线连接到信息气泡。
  - 引导线需要有角度，不是单纯直线。
- 信息气泡应尽量显示在空一点的位置。
- 气泡信息需要位于最上层，不能被其他容器遮挡。
- 交互要求：
  - 鼠标移动后显示要丝滑。
  - 不应有明显延迟。
  - 信息位置要贴近当前扇区，不应对不准。

## 11. 公共区域管理与主地图展示

- 空间管理中公共区域支持多点框选范围。
- 公共区域范围直接显示在主工作台地图上。
- 主工作台展示公共区域时：
  - 只需要半透明区域颜色。
  - 不需要显示明显边框。
  - 中间文字标签颜色可以淡一点。
- 后台空间管理编辑公共区域时：
  - 可以点击空白地图新增顶点。
  - 点击已有顶点时应移动该点，不应新增点。
  - 标记点位数字圈要精细，地图越放大，数字圈视觉上越小。
  - 框选时不能只支持滚轮缩放，也要能按住拖动画布。
- 楼座列表移动到下方，与房间列表平齐。
- 上方更多空间留给地图编辑区，方便框选公共区域和主体范围。
- 新增场地/公共区域列表放在右侧，宽度和高度应与左侧地图编辑区协调，底部基本齐平。

## 12. 后台毛玻璃与背景可读性

- 项目整体保留半透明毛玻璃 UI 和自定义背景图。
- 可读性问题不能靠完全取消透明效果解决。
- 优先方案：
  - 给页面背景增加柔和遮罩。
  - 提高玻璃容器本身不透明度。
  - 提升文字对比度。
  - 关键 tooltip、按钮、表格头部使用更稳定的可读底色。
- 后台背景不应出现一格格网格纹路。
- 背景整体不应灰雾感过重。
- 容器透明度不能太透，要在保留玻璃感和文字清晰之间取平衡。

## 13. 当前优先口径

- 统计页中「超时任务」以已完结超时为准，不等同于主工作台实时「当前已超时」。
- 统计页中「贡献值」以助理综合评分为准，不用点赞/点踩加减分。
- 部门筛选以人员资料 `department` 字段为准。
- 楼座筛选以任务实际发生楼座为主，即 `locationBuildingId` 优先。
- 任务类型展示和统计优先使用五类简化口径。

## 14. 待就位任务提权与派发一致性

- 普通等待提权不只作用于未分配助理的任务，也作用于已经分配助理但尚未就位的 `waiting` 任务。
- 只要任务尚未真正开始执行，就可以按等待时长进入提权判断，避免低优先级任务因为已经分配助理但迟迟未就位而长期沉底。
- 已分配待就位任务的等待起点优先使用主助理参与记录的 `joinedAt`。
- 如果缺少参与记录或 `joinedAt`，再回退使用任务 `createdAt`。
- 摄影师发布上限锁住的任务仍不参与普通等待提权。
- 待就位插单仍要求新任务优先级更高，即优先级数值更小。
- 系统主动扫描待分配任务时，行为应与摄影师新建任务后的派发行为一致：
  - 优先匹配同楼座空闲助理；
  - 没有空闲助理时，再进入待就位让行/公共队列等规则；
  - 不能出现创建任务可以触发的逻辑，扫描任务时永远不会触发。

## 15. 工作台中心地图与区域任务数据

- 中心地图区不再只是单一地图，应作为当前区域的工作容器。
- 容器包含两个页面：
  - `楼层平面图`：保留地图、头像标记、拖动、缩放和底部状态图例。
  - `任务数据`：展示当前区域任务概览、区域进行任务、助理状态、任务类型占比等。
- `任务数据` 页面用于解释当前区域运转情况，不改变左侧「我的任务」和公共队列的业务归属。
- 地图容器视觉应与任务列表保持一致：圆角、半透明、柔和边框、毛玻璃质感。
- 地图底部图例需要与右侧助理 Dock 保持同一套状态口径：
  - 空闲中；
  - 待就位；
  - 进行中；
  - 已超时；
  - 已下线。
- 地图状态颜色应与 Dock 状态点同源，避免同一个助理状态在不同区域显示成两套含义。

## 16. 区域任务数据看板人员气泡

- 区域任务数据看板中，除「今日已完成」外，其余实时指标都可以展开人员气泡。
- 可展开指标包括：
  - 正在进行中；
  - 等待就位中；
  - 当前已超时；
  - 公共队列中；
  - 离线人员。
- 摄影师身份查看时，任务型指标优先解释「是谁发布的任务」，因此显示发布任务的摄影师头像。
- 助理身份查看时，实时人员型指标优先解释「哪些助理处于该状态」，因此显示助理头像。
- 「公共队列中」始终是任务队列口径，无论摄影师还是助理查看，都显示队列任务发布摄影师头像。
- 助理视角的「等待就位中」需要包含公共队列里已经分配助理、但助理尚未就位的任务。
- 「当前已超时」气泡必须拆分超时来源：
  - 任务超时；
  - 吃饭超时。
- 摄影师视角的超时数字和超时气泡明细必须同源，不能出现主数字有值但气泡为空。

## 17. 右侧助理 Dock 与头像备注

- 右侧助理 Dock 的状态点与地图底部图例使用同一状态口径：空闲中、待就位、进行中、已超时、已下线。
- 右侧 Dock 中的备注长文本最多显示两行，避免挤压头像列表和状态文案。
- 摄影师在右侧 Dock 点击助理头像打开备注时，备注框应贴近被点击头像显示，而不是居中遮罩。
- 备注框需要做屏幕边缘限制，不能因为头像靠近视口边缘而跑出屏幕。
- 点击空白处、取消或保存后，备注框关闭。
- 地图头像备注提示也应使用同一套两行截断规则，保持 Dock 和地图展示一致。

## 18. 任务备注与助理知悉

- 摄影师备注输入框使用示例提示，例如 `如：需要带一个道具...`。
- 助理身份的「当前任务状态」卡片不直接显示备注正文，避免工作状态区变得拥挤。
- 助理收到带备注任务时，在页面中心弹出「摄影师备注」毛玻璃浮窗。
- 备注浮窗需要展示足够上下文：
  - 摄影师；
  - 房间；
  - 任务类型；
  - 摄影师选择的时长；
  - 备注正文。
- 助理点击绿色「已知悉」后关闭当前备注浮窗。
- 同一条任务备注在当前页面已知悉后，不应立即重复弹出。
- 备注浮窗整体尺寸需要适合现场快速阅读，正文、标题和按钮不能过小。

## 19. 助理楼座切换入口

- 助理楼座切换不再作为右侧独立按钮列展示。
- 楼座切换入口挂在助理头像名片的地址/楼座文字区域。
- 只有进入地址区域时，才展开楼座切换菜单。
- 展开菜单需要保持在地图和任务面板之上，避免被中心地图容器裁切。
- 助理执行中任务时仍不应随意切换楼座；切换能力必须服从既有任务状态限制。

## 20. 熨烫机管理与工作态口径

- 后台「空间管理」中新增熨烫机管理能力。
- 熨烫机归属于具体楼座/区域。
- 后台可以手动添加熨烫机数量，默认按数字序号生成名称，例如 `熨烫机1`、`熨烫机2`。
- 熨烫机状态可调整：
  - 正常运行；
  - 维修不可用。
- 熨烫机不再作为前台地图中的可拖拽点位展示；后台仍保留新增、删除、正常/维修状态管理。
- 前台地图右上角固定展示熨烫机接续区，每台熨烫机一行：
  - 进行中机器显示红色熨斗图标；
  - 空闲正常机器显示绿色熨斗图标；
  - 维修不可用机器显示灰色熨斗图标；
  - 机器行按 `进行中 → 空闲 → 维修不可用` 排序，同状态内按后台排序和机器 id 稳定排序。
- 右上角熨烫机接续区不使用外层底框/玻璃面板，常态只显示熨烫机图标与助理头像。
- 右上角头像与地图头像是两个并行状态维度，不互斥：
  - 右上角表达机器接续、准备和排队顺序；
  - 地图表达助理所在任务位置；
  - 准备熨烫头像应同时出现在机器接续区和对应任务房间地图上。
- 正在使用熨烫机的助理头像显示在对应机器图标左侧；一台正常运行机器同一时间最多绑定一个正在使用助理头像。
- 等待或准备熨烫的助理头像从机器图标左侧继续向左排列，不推动机器图标位置。
- 队列头像 hover 文案：
  - 如果同一行前面已有正在使用助理，后续头像显示 `队列中`；
  - 如果前面没有正在使用助理，空闲机器旁的准备助理显示 `准备熨烫` 或 `等待熨烫机`。
- 熨斗 hover 只显示机器状态：`使用中 / 空闲 / 维修不可用`。
- 助理头像 hover 显示熨烫任务信息：
  - 标题为 `x分钟熨烫任务`，超过 60 分钟用小时并保留 1 位小数；
  - 未超时时显示 `已进行x分钟` 与 `预计剩余时间x分钟`；
  - 已超时时只显示任务标题和 `已超时x分钟`。
- 任务时长使用任务类型配置的时长口径，与快捷预约按钮一致。
- 熨烫任务识别口径：
  - 任务类型归组为「熨烫」；
  - 或任务类型名称包含「熨」。
- 开始熨烫任务前，后端必须校验同楼座正常运行熨烫机容量；可用机器已满时返回明确提示，不允许进入执行中。
- 机器全满时，不按固定机器号或简单轮询排队；等待头像按每台机器预计可用时间轴动态分配，排在前面的等待任务预计时长也要计入该机器后续可用时间。
- 有空闲机器时，准备熨烫助理头像直接挂到空闲机器左侧，不应继续排到忙碌机器后面。
- 维修不可用机器不参与可用数量和执行容量计算。

## 21. 后台空间管理地图编辑口径

- 空间管理的地图编辑区域需要给公共区域框选、房间点位和主体范围框选留出足够空间。
- 楼座列表放在地图下方，并与房间列表平齐。
- 右侧新增场地/公共区域列表高度应尽量与地图编辑区底部齐平。
- 右侧栏顺序以管理频率为准：公共场地/其他场地在上，熨烫机管理在下。
- 熨烫机管理容器使用“添加熨烫机”操作，点击一次新增 1 台，不再提供“新增台数”输入。
- 熨烫机管理列表展示 `熨烫机1、熨烫机2...`，不显示地图坐标和“可拖拽定位”类文案。
- 公共区域支持多点框选范围。
- 公共区域范围应直接显示在主工作台地图上。
- 主工作台展示公共区域时，以半透明区域颜色为主，不需要明显边框。
- 后台编辑公共区域时：
  - 点击地图空白位置新增顶点；
  - 拖动已有顶点时移动该点；
  - 点击已有顶点不能穿透成新增点；
  - 框选时既支持滚轮缩放，也支持按住拖动画布。
- 标记点、数字圈和编辑线条需要克制，不能遮挡地图主体信息。

## 22. 熨烫任务、助理等待与自动均衡口径

- 熨烫任务具有独立阶段：
  - `none`：普通任务默认阶段；对于历史/普通待就位熨烫任务，若已经分配助理且仍是 `waiting`，也视为未开始熨烫等待；
  - `waiting_machine`：已有负责人，但没有可用熨烫机；
  - `notified`：熨烫机已空出或即将可用，已通知负责人准备熨烫；
  - `using`：助理已开始熨烫，实际占用机器。
- 未开始熨烫等待不等于助理正在工作：
  - `waiting_machine`、`notified`、以及 `waiting + 熨烫 + 已分配 + stage=none` 都不应计入真实执行占用；
  - 只有 `executing/paused/using` 等真实执行或暂停状态才算占用助理或机器。
- 普通新任务派发候选不能只看 `profile.status=idle`：
  - 助理可能因为未开始熨烫等待显示为 `assigned`；
  - 只要她在线、无微标签、同楼座，且没有真实执行/暂停/普通待就位/协作任务，就可以接普通新任务。
- 系统派发普通任务时，优先找同楼座真正空闲助理；如果某助理只挂着未开始熨烫等待，也可以作为可派发候选。
- 熨烫机空档处理顺序：
  - 先处理待就位超时换人；
  - 再释放超过保护期仍未开始的 `notified` 机器使用权；
  - 再扫描熨烫机队列；
  - 再做熨烫等待负载均衡；
  - 最后再派发普通未分配任务。
- 熨烫机使用权保护：
  - 当机器空出后，队首熨烫任务进入 `notified`；
  - 默认保护 2 分钟，可在后台「逻辑设置」调整；
  - 超过保护期仍未开始，释放机器使用权，任务回到 `waiting_machine` 并刷新排队时间，避免空机器被长期占住。
- 等待熨烫期间，系统可以继续给负责人派发其他更合适或更高优先级的普通任务；这不应取消她的熨烫等待身份。
- 当同楼座有空闲可派发助理时，未开始熨烫等待不能无限集中到同一人：
  - 若某助理身上超过 1 条未开始熨烫等待，且同楼座存在 0 条熨烫等待的可派发助理，系统自动转出额外等待任务；
  - `notified` 代表已获得机器使用权/准备熨烫，优先保留给当前负责人；
  - `waiting_machine` 和历史 `stage=none` 的额外等待任务优先被均衡给其他空闲助理；
  - 转派会把旧 primary 参与记录标记为 `left`，给新助理创建/更新 primary waiting，并记录原因为 `ironing_wait_load_balance`。
- 普通待就位任务与熨烫等待的关系：
  - 如果负责人只是等待熨烫机，她仍可先处理其他普通待就位任务；
  - 普通任务只有在负责人真正去熨烫后，超过待就位超时阈值才可转派给其他空闲助理；
  - 不能因为她还在等待机器，就提前把她的普通待就位任务转走并让她自动离线。
- 多个可行动待就位任务展示：
  - 如果助理同时有普通待就位和 `notified` 准备熨烫，工作台当前任务状态应展示多个可点击入口，让助理选择先开始哪一条；
  - `waiting_machine` 没有机器可用，不可点击开始，只作为等待提示；
  - 单条 `notified` 熨烫任务可点击开始熨烫。
- 地图与右上角机器接续显示不互相覆盖：
  - 地图上继续显示助理所在任务房间头像；
  - 右上角同时显示该助理的熨烫机接续/准备/队列状态。
- `notified` 是临时机器使用权，不是真正开始使用机器；只有助理开始任务并进入 `using/executing` 后，才算实际占用熨烫机。
