## 1. 助理综合排行

- 综合分只按实际贡献计算，不按摄影师预估时间扣分。
- 公式：`综合分 = 实际服务时长(1小时=1分) + 完成任务数 * 0.2 + 跨区次数 * 0.2`。
- 任务数补贴：每完成 1 个任务额外加 `0.2` 分。
- 跨区补贴：同一助理今日完成任务按完成时间排序，相邻任务楼座/区域发生变化时计 1 次，每次加 `0.2` 分。
- 跨区示例：`南座四楼 -> 北座三楼 -> 北座三楼` 只计 1 次跨区。
- 设计原因：摄影师预估时间可能不准确，实际预约时间短于服务用时不应扣分；4 个半小时任务虽然总服务时长等于 2 小时，但存在多次任务切换和可能的区域移动，投入成本应高于单个 2 小时任务。
- 示例：
  - 助理 A：完成 1 个 2 小时任务，得分 `2 + 1 * 0.2 = 2.2`。
  - 助理 B：完成 4 个各半小时任务且同区域，得分 `2 + 4 * 0.2 = 2.8`。
  - 助理 C：完成 4 个各半小时任务且中间有 1 次跨区，得分 `2 + 4 * 0.2 + 1 * 0.2 = 3`。

## 2. 实际服务时长

- 排行、任务明细等服务贡献应优先使用实际有效工作时长。
- 暂停、等待就位、插单占用等非真实服务时间不计入实际服务时长。
- 预约/预估时间可用于排队、展示和部分调度判断，但不作为助理完成结果的扣分依据。

## 3. 公共队列与任务数据页

- 任务数据页按当前区域展示数据，核心分为：公共队列、助理排行、任务类型。
- 公共队列展示当前区域队列任务，并复用公共队列原有排序、排名、提权标记、待就位超时标记、本人任务高亮与插入动画。
- 普通队列提权只作用于未分配助理的队列任务。
- 已派发给助理但尚未开始的待就位任务，不参与“未分配队列任务等待多久提权”的普通提权逻辑。
- 任务数据页中的任务类型、统计卡、助理状态属于区域数据分析，不改变派发逻辑。

## 4. 执行中插单与待就位让行

- 必须区分两类路径：
  - 执行中插单：助理正在执行低优先级任务，新高优先级任务尝试打断当前任务。
  - 待就位让行：助理已分配低优先级任务但尚未开始，新高优先级任务先占用该助理，原任务保留等待。
- 执行中插单必须严格遵守后台任务类型规则：
  - 任务类型是否允许插单。
  - `30` 分钟以内任务不可插单。
  - 最大离场时间限制。
  - 优先级必须更高。
  - 锁定任务不可插单。
- 待就位让行属于队列重排，不套用任务类型“可被插单 / 30 分钟内不可插单 / 最大离场时间”限制。
- 待就位让行仍需满足基本安全条件：新任务优先级更高、原任务未开始、没有重复让行子单、助理没有其他活跃插单。
- 同一助理已有未完成插单任务时，不再继续叠加新的临时接派任务。

## 5. 摄影师任务发布上限

- 后台可配置摄影师最大未完成任务数。
- 未完成任务统计口径包含 `waiting / executing / paused`。
- 达到上限后，不直接拒绝摄影师创建任务，而是创建摄影师个人队列任务。
- 个人队列任务使用 `isLocked + lockReason` 标记，不新增额外字段。
- 个人队列任务不进入公共队列、自动派发、空闲认领、全局扫描和动态提权。
- 当摄影师未完成任务数低于上限时，系统自动释放最早的个人队列任务进入正常派发队列。
- 摄影师端显示为灰色“队列中”，并提示：当前摄影师已达到最大任务发布量，待上一任务完结后进入公共队列排队。

## 6. 多人协作任务

- 多人协作资格按任务时长判断：`maxDuration > 30` 或 `minDuration >= 30`。
- 该口径覆盖 `30-60分钟` 与 `60分钟以上` 任务。
- 主助理和协作助理统一抽象为任务参与者：
  - 主助理：`primary`。
  - 协作助理：`helper`。
- 每个参与者拥有自己的状态和时间线：待就位、进行中、暂停、完成、离开。
- 单个参与者完成后，只释放该助理个人；任务整体必须等所有未离开的参与者都完成后才算完成。
- 协作中的助理不应被自动派发新任务，也不应进入执行中插单或待就位让行候选池。
- 协作助理端可以看到自己的协作任务状态，但不能操作主助理的开始、完成、暂停按钮。
- 摄影师和当前主助理可以维护协作名单；协作助理不能继续添加其他协作助理。
- 新增协作候选必须满足：同任务区域、在线、空闲、无活跃主任务、无活跃协作参与记录。

## 7. 多人协作开关、人数与队列拥堵

- 后台按大区配置“多人协作规则”开关，默认开启。
- 大区关闭新增协作后：
  - 禁止新增协作助理。
  - 保留已有协作展示。
  - 允许移除已有协作成员。
- 后台配置的“最多 N 人”指任务总参与人数，包含主助理。
- 可额外选择的协作人数 = 总上限 - 当前主助理与已有参与者。
- 当前区域公共队列达到自动关闭阈值时，新增协作入口关闭。
- 队列拥堵自动关闭只影响新增协作，不影响已有协作任务继续展示、移除或完成。

## 8. 待就位超时自动换人

- 已派发但未开始的待就位任务，如果原助理长时间未应答，可在有新的空闲在线助理释放时触发自动换人。
- 默认复用后台 `upgrade_threshold` 作为待就位未响应阈值。
- 换人只在同楼座/同服务区域内寻找新的空闲在线助理。
- 换人优先级按“任务等级分 + 超时等待分”排序：任务越急、超时越久，越优先接替。
- 换人事务中：
  - 任务主助理切换为新助理。
  - 原主助理参与记录标记为 `left`。
  - 新助理写入 `primary / waiting`。
  - 任务备注保持不变。
  - 原助理是否离线需要单独判断，不与换人动作绑定。
- 自动换人和自动离线必须解耦：
  - 如果原助理仍有其他进行中/暂停中的主任务或协作任务，只移除她在这条超时待就位任务里的参与关系，不得切为离线；她继续按实际任务显示为进行中或在忙。
  - 如果原助理没有其他进行中/暂停中的工作，才可以切为 `offline + idle`，避免继续派单。
- 新助理收到接替提醒；原助理只有在被系统切离线时才需要收到离线恢复提醒，确认后可恢复在线空闲。

## 9. 助理吃饭/在线状态

- 不使用人员 `updatedAt` 推算吃饭中持续时间。
- 吃饭状态必须有独立字段记录开始/结束时间：`eatingStartedAt / eatingEndedAt`。
- 离开吃饭后进入再次切回吃饭的冷却期，默认 `30` 分钟。
- 冷却期由后端接口强制校验，前端失败时应回滚乐观状态并显示等待提示。
- 吃饭超时判断使用独立的 `eatingStartedAt`。
- 在线、吃饭、休假/下班这类会影响派发候选池的状态变更，需要经过当前身份本人及任务状态校验。

## 10. 状态与地图展示口径

- 地图和 Dock 状态统一为：空闲中、待就位、进行中、已超时、已下线。
- 暂停任务需要区分来源：
  - 手动暂停：普通任务由助理主动暂停。
  - 插单暂停：因紧急插单或父子任务关系导致的暂停。
- 多人协作中单个协作助理暂停时，地图保留该助理在任务位置的暂停头像，并按该助理自己的参与记录计算暂停耗时/超时。
- 已完成的多人协作任务在任务卡中展示主助理和协作助理姓名，并可用“多人协作完成”标记区分。

## 11. 当前最终口径优先级

- 若历史记录中出现“待就位让行是否应遵守不可插单规则”的不同表述，以当前最终口径为准：
  - 执行中插单：严格遵守可插单、30 分钟、最大离场时间等任务类型限制。
  - 待就位让行：视为队列重排，不套用任务类型不可插单限制。
- 若前端入口与后端接口口径不一致，以后端强校验为准，并同步前端展示条件，避免“前端可点但接口拒绝”或“接口绕过前端规则”。
